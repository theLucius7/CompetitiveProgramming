代码与归档规范 ​

以下是后续新增和修改的约定。历史代码保留原样，不将已有风格、通过状态或复杂度补写成未经验证的结论。

路径与命名 ​

新增文件优先沿用同一平台的现有惯例：项目结构。使用原始题号，不仅使用题目标题；保留题号大小写，尽量选用稳定的 ASCII 文件名。已有中文、空格和大小写路径保持兼容，命令中用引号包裹路径。

一道题的默认提交文件位于该平台目录。若需保留多种实现或错误尝试，使用含义明确的后缀，例如 _bruteforce、_stress、_wa，并在文件注释或伴随笔记说明状态。不要新增 copy、backup 等无法辨别意义的备份。

缺少原题信息的草稿先保留可追踪位置和状态，不猜测平台归属。确认需要迁移时使用 git mv，并检查 CPH 导入规则、网页链接推导和数据快照；迁移与算法修改分开提交。

单题代码 ​

每份提交代码应可在目标 OJ 独立编译，不依赖本机绝对路径或仓库外的私有头文件。使用标准输入/输出；删除调试输出和本机重定向。提交前确认整数范围、数组容量、递归深度、时间复杂度和空间复杂度适合题目限制。

局部修改遵循文件现有缩进。新文件可使用四空格或沿用竞赛模板的制表符，但不在一个代码块内混用；避免为格式化重写整份历史代码。新增内容采用 UTF-8，文档和脚本使用 LF 换行。

注释优先解释状态定义、循环不变量、边界处理和难以推导的转移。简单语句不逐行翻译。简短竞赛变量名可以保留；公共模板的参数与前置条件必须可理解。

来源与验证状态 ​

新增题解或整理旧题时，可使用下面的最小头部。只有存在证据才填写 AC、提交链接或复杂度；未知项明确写未知，也可以省略。

cpp
// Problem: https://atcoder.jp/contests/abc231/tasks/abc231_a
// Status: sample-checked
// Checks: input 1000 -> output 10.000000
// Time: O(1), Space: O(1)
状态最低证据
draft尚未完成或尚未运行
compile-checked记录编译器、标准和成功编译
sample-checked运行并比对所列样例；不推出全数据正确
acOJ 返回 Accepted，尽可能附提交链接和评测时间

Git 提交时间记录仓库修改时间，与 OJ 评测时间是两个概念。不要将它们混用。现有文件没有状态头时视为状态未记录。

较长题解放在源码旁的同名 .md，只需：原题链接、关键思路、正确性要点、复杂度、验证记录。避免复制完整题面，方便回到原站查阅限制。

模板 ​

新增或修改模板时说明用途、接口、下标区间、初始化、数值范围、复杂度和依赖。至少用一个最小程序覆盖正常调用与边界。不要把模板片段当作独立提交文件，也不要仅因已有文件名就假设其实现已经稳定。

提交范围 ​

样例、二进制、日志和本机缓存遵循 .gitignore。该文件使用默认忽略的白名单：新增配置或非现有语言文件前检查 git check-ignore -v <路径>，按需放行精确路径，不使用全仓强制添加。

详细步骤和提交格式见贡献指南。
